★ Transparent Risk Scoring Methodology

CYBERTRACE implements an explainable, deterministic scoring model. Unlike black-box machine learning models, every risk point addition is directly traced to a verified indicator:

Indicator / Event Category Added Points Security Rationale
Failed login burst +20 High-frequency password guessing or brute-force behavior.
Successful login after failures +20 Indicates potential credential compromise following brute-force attempts.
Privilege escalation +25 Elevation to root/administrator rights indicates severe lateral compromise.
Suspicious external connection +20 Outbound traffic to public IP addresses indicates potential C2 or data staging.
Account lockout +10 Security threshold exceeded resulting in denial of authorized access.
Multiple correlated indicators +15 Convergence of multiple distinct attack steps from identical source entity.

Essential Viva Questions & Answers:

1. What is the fundamental difference between an Event and an Incident?
An Event is any observable occurrence on a system (such as a single failed login or file creation). An Incident is an event or series of correlated events that adversely affects or threatens the security and confidentiality of a system.
2. What is an Indicator of Compromise (IOC)?
An IOC is a forensic artifact observed on a network or operating system that may indicate a security breach, such as an external IP address, malicious domain, unauthorized username, or staging file path.
3. Why use deterministic rule-based detection instead of machine learning?
Deterministic rules provide 100% explainability. In a Security Operations Center and academic viva, an analyst must explain exactly why an alert triggered. Black-box ML models produce false positives and lack explainability.
4. How does the Event Correlation engine work?
The correlation engine groups events sharing the same Source IP or Username within a sliding time window, and tracks progression from initial access (brute-force) to compromise (success), elevation (sudo), and command communication.
5. Does CYBERTRACE prove that an attack happened?
No. CYBERTRACE identifies potential attack patterns. Definitively confirming an attack requires physical forensic verification and context, which is why defensive SOC wording is used.
